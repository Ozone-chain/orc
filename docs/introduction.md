# Introduction to ORC

**ORC (Ozone Request for Comments)** is the official technical standards and proposal system for **Ozone Chain**.

---

## 1. What is ORC?

ORC provides the formal framework for defining, discussing, and formalizing application-level standards, token specifications, smart contract interfaces, and developer conventions across the Ozone Chain ecosystem.

Similar to how the IETF uses RFCs and Ethereum uses EIPs/ERCs, Ozone Chain uses ORCs to ensure consistent developer experience, deterministic tooling compatibility, and robust security.

---

## 2. What ORC is Not

- **ORC is NOT a Consensus Fork**: ORC does not alter the underlying Ozone Chain consensus protocol, block structure, or EVM execution semantics.
- **ORC is NOT Incompatible with Ethereum**: ORC-20 is 100% ABI and function-selector compatible with ERC-20.
- **ORC is NOT a Marketing Slogan**: All standards must include testable specifications, formal security analyses, and reproducible benchmarks.

---

## 3. Why Does Ozone Chain Need ORC?

1. **Standardized Interoperability**: Ensures all wallets, DEXes, bridges, and explorers speak the exact same contract language.
2. **Clear Quality Standards**: Establishes a four-tier certification process to help users and dApp integrators evaluate token contract reliability.
3. **Structured Community Participation**: Empowers builders to propose and champion new standards through an open, transparent editorial process.
4. **Future Proofing**: Provides a structured path for introducing advanced standards such as tokenized vaults (ORC-4626), gasless permits (ORC-2612), and quantum-safe application verification modules without fragmenting the ecosystem.
